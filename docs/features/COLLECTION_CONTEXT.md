# Collection and device context
Schema v10 adds a stable library_identity (ID, editable name, revision). Backup/restore retains the library identity. A separate atomic, lock-protected device.json records the local installation identity and readable computer name; it is not catalog backup data. The desktop passes its base device directory when starting restored catalogs, so a restore changes catalog identity when appropriate without changing this computer's ID. A malformed device file fails closed rather than inventing a replacement ID. Independent standalone data directories have independent device identities unless explicitly launched with the same device directory.

GET /api/context requires authentication and reports collection, Core computer, process instance, API version range and role-specific capabilities. POST uses revision checking to rename the collection. The current implementation truthfully reports loopback Windows Core, acquisition on Core, no remote acquisition, separate per-source availability and per-request provider status. It does not claim NAS deployment or remote desktop-worker support.

Current frontend writes include X-Galroon-Library and X-Galroon-Device; authenticated Core checks mismatches before routing (409). Headers are optional for legacy API clients, so this does not replace authentication. Responses expose the IDs for normal Web sessions. Native session replies include both IDs and supported API range. Automatic reconnect cannot adopt a different library/device: drafts stay mounted with inert controls until explicit discard/open reloads the app. Unsupported API versions pause controls without a retry loop. Explicit backup restore also reloads the app to discard old views/caches. Acquisition default destinations are now scoped by library/device; the old global preference is not silently carried into another collection.
