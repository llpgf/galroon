# Galroon 使用者故事與端到端驗收（第一批）

> 來源：2026-10-10 需求問答。本文件定義「要做什麼」；每條故事下的驗收條件就是端到端測試要驗證的「是否真的做到了」。

## 範圍與前提

- **角色**：重度收藏者（我自己）。上百到上千部 galgame，多版本、日文/全形檔名、純數字或商品碼資料夾、特典與音樂另放。
- **本批範圍**：① 加入來源 → 掃描 → 匹配；② 瀏覽收藏與作品頁；③ 清單與標籤。
  不含：檔案整理/搬移、Get files、備份還原、連線配對（之後另批）。
- **兩層測試環境**
  - **M（Mac 自動化層）**：`ui_core` + Vite，Playwright 驅動瀏覽器；資料用唯讀 NAS 測試集（38 個頂層資料夾，`GALROON_TESTSET` 指向外接 SSD 上的 `/Volumes/新增磁碟區/galroon-testset-2026-10/`）＋真實 VNDB；見[遷移計畫](../plans/2026-10-16-e2e-nas-test-set.md)與[答案卷](../../tests/e2e/golden/nas_testset.json)。每次測試用全新的 GALROON 資料目錄，不碰真實收藏。
  - **W（Windows 原生層）**：在測試筆電用 NSIS 安裝檔走一次完整流程。已自動化：`scripts/windows/acceptance.ps1` 靜默安裝、以全新 `GALROON_DATA` 在登入中的桌面開啟 app（WebView2 遠端除錯埠只綁 127.0.0.1），再由 `tests/windows/`（`playwright.windows.config.ts`）操作真實視窗。
- **完成定義**：所有故事的 M 層測試全綠 ＋ golden 對照錯配數 = 0 ＋ W 層安裝流程走過一次。測試發現 bug → 修 → 重驗，直到綠燈。
- **共通規則（適用每條故事）**
  - **G1 絕不錯配**：寧可留待處理，也不把資源綁到錯的作品。錯配是硬性失敗。
  - **G2 錯誤要看得懂**：每個失敗都顯示人話原因 ＋ 可操作的下一步（重試／繼續／前往處理）。不得出現空白頁、無限轉圈、或只有錯誤碼。
  - **G3 不動檔案**：掃描、匹配、瀏覽、清單、標籤都不得改動、移動或寫入來源資料夾裡的檔案（測試前後比對來源目錄的檔案清單與大小／修改時間）。

## 標準答案（golden）

「絕不錯配」需要答案卷：[`tests/e2e/golden/nas_testset.json`](../../tests/e2e/golden/nas_testset.json)。NAS 測試集共 38 個頂層資料夾，複本在外接 SSD 的 `/Volumes/新增磁碟區/galroon-testset-2026-10/`（exFAT，無法設唯讀；G3 指紋比對照樣檢查是否被寫入），以必填的 `GALROON_TESTSET` 指定；沒有預設路徑。見[遷移計畫](../plans/2026-10-16-e2e-nas-test-set.md)。

2026-10-16 由 owner 逐筆審核定稿。舊 [`sandbox_data.json`](../../tests/e2e/golden/sandbox_data.json) 保留為歷史紀錄，不再用於驗收。

- `work`＝VNDB ID；`works`＝合集，綁定集合須完全一致；多綁任何其他作品都是錯配。
- `remake_release`＝以重製版發行資料建獨立卡；`same_edition_as`＝同卡、同版本；`bonus_only`＝只有特典。
- `split`＝各成員分別配對、各算一列；`manual`＝允許留待手動，手動綁定仍須符合答案。
- `unmatched: true`＝必須保持未配，任何綁定都算錯配。
- 有答案卻未配或合集少綁 → 未配，計數；錯配 → **測試失敗**。卡片數按作品去重，故障恢復門檻按非 `manual` 列數計算。

## 一、加入來源 → 掃描 → 匹配

### US-1.1 加入來源後自動出現封面卡（正常流程）
**作為**收藏者，**當我**在 Sources 加入 NAS 測試集資料夾並儲存，**我要**不按任何其他按鈕，Collection 就逐漸出現帶封面的作品卡，**以便**不用手動逐部整理。

驗收（M）：
1. 全新資料目錄啟動 → Sources 加入 NAS 測試集 → 儲存。之後**不再點擊**掃描或匹配。
2. Activity 依序出現掃描任務與匹配任務，進行中可見進度；結束後摺疊。
3. 在時限內（掃描約 1 分鐘＋匹配時間，上限 10 分鐘）任務完成。
4. Collection 預設「最近加入」排序，作品卡數量與 golden 預期一致；每張已配卡片顯示封面圖（圖片實際載入成功，非破圖）。
5. 依 golden 對照：錯配 = 0、每列符合 golden（`manual` 與 `unmatched` 可保持未配）。
6. Updates 通知出現，數字是「資源數」，連結可前往 Collection 或待處理清單。
7. G3：來源目錄檔案未變。

### US-1.2 同一作品多份資源合成一張卡
**當**來源裡有同一作品的兩份資源（`生命のスペア` 與 `生命のスペア.rar`，同為 SPARE.iso），**我要**只看到**一張**作品卡，底下是**一個版本、兩個資源**。

驗收（M）：
1. 掃完後 Collection 搜「生命のスペア」只得到 1 張卡。
2. 作品頁版本區：1 個版本，內含 2 個資源，各自顯示實際路徑。
3. 不得出現兩張同名卡，也不得把兩份資源拆成兩個版本。
> ⚠ 需求差異：目前兩份都留在未配（原因：只有部分標題），且自動匹配給每份資源各自的 unclassified 版本。

### US-1.3 多作品特典資料夾拆開配對
**當**來源裡有一個資料夾裝著**多部不同作品**的特典（`WaffleTokuten`：善悪、恋愛弱者な幼馴染少女…、奴隷姫騎士…、人間不信の錬金術師… 各自的特典 rar），而這些作品本體不在收藏中，**我要**它被拆成多個資源、各自配到所屬作品；只有特典沒有本體的作品卡標示「只有特典」，可在 Collection 篩選掉。

驗收（M）：
1. `WaffleTokuten` 不成為一張卡，也不留一整包未配。
2. 依 golden 的 `split`：7 個 rar 各自成為資源；5 個自動配到 v51928、v30998、v36749（3 張卡）。「善悪」只有 2 個字，依既有的短標題防錯配規則（同「[Key] AIR」）留待手動處理，golden 標為 `manual`，手動綁定見 US-1.5。
3. 這些卡顯示「只有特典」標記；作品頁資源區把它們列為特典。
4. Collection 可用篩選隱藏「只有特典」的卡；隱藏後計數正確。
5. 之後若加入其中某作品的本體 → 同一張卡變為正常卡（不再標「只有特典」），不出現第二張卡。
6. 辨識不出所屬作品的成員 → 單獨留待處理並說明原因，不拖累其他成員；絕不配錯（G1）。
> ⚠ 需求差異：目前整個資料夾是一個資源且未配；沒有拆分與「只有特典」標記。
> 假設：「リマスター」（重製畫質）視為同作品的版本；只有「リメイク」（重製）走 US-1.9 的獨立卡。

### US-1.9 重製版建立獨立卡
**當**資源是重製版（`下級生リメイク`、`夜勤病棟リメイク`），而 VNDB 把重製版放在原版條目下的一筆發行資料，**我要**得到一張重製版自己的卡：標題、發售日、品牌、封面用重製版發行資料；角色等沿用 VNDB 原條目。將來若也收了原版，是另一張卡且兩者互相關聯。

驗收（M）：
1. `下級生リメイク` 的卡標題為「下級生リメイク」、發售日 2025-12-19、品牌 FG Remake（golden `remake_release` r140695）；不是 1996 年 elf 的「下級生」。
2. `夜勤病棟リメイク` 同理（r114394，2024-02-22）。
3. 作品頁的角色／工作人員仍有內容（沿用原條目）。
4. 若另有原版資源配到同一 VNDB 條目 → 兩張卡，作品頁互相顯示關聯。
5. 重抓 VNDB 資料不會把卡面改回原版資料。
> ⚠ 需求差異：目前兩者都直接配到原版條目並顯示原版資料。

### US-1.4 怪檔名正確辨識
**當**資料夾名是純數字（`1368659`）、DLsite 商品碼（`VJ01001192`）、含日文全形／`[]`／`～`、帶 `豪華版 + Voice Drama + Theme Song` 等附註、或含續作編號（`猫忍えくすはーとSPIN！ 2`），**我要**系統用合理線索（內部檔名、去除附註後的標題）辨識，續作編號不得配到前作。

驗收（M）：以 golden 為準逐項比對；特別檢查：
- `1368659` → v65539（くりくりクリニック ～新人ナースの育て方～）。
- `猫忍えくすはーとSPIN！ 2` 不得配到無編號的前作或其他續作。
- `下級生リメイク` 依 US-1.9 成為重製版獨立卡。
- 商品碼不被當成 VNDB ID 使用。
- `VJ01001192`（DLsite 商品碼）必須被辨識：先用內部檔名線索；不足時以商品碼查詢其對應作品標題（例如 DLsite 商品頁）再走一般標題匹配。仍無法確定時留待處理並說明原因（G1 優先）。
- 任何配不到的項目都顯示「為何未配」原因。

### US-1.5 配不到的資源手動綁定
**當**某資源留在待處理，**我要**看原因 → 搜 VNDB → 從候選中選一個 → 確認，綁定後立刻出卡；之後重新掃描或重新匹配**絕不覆蓋**我的手動綁定。

驗收（M）：
1. 待處理列顯示原因（缺標題／只有部分標題／歧義／名稱衝突／VNDB 結果不完整）。
2. 開啟搜尋 → 改查詢字 → 候選列表顯示標題、證據與衝突警告。修改查詢時舊結果被丟棄。
3. 選候選並確認 → 待處理減 1、Collection 多一張帶封面的卡（或併入既有卡）。
4. 執行「重新匹配」與「重新掃描」→ 該綁定不變。
5. 異常：確認時若資料已被其他操作改動 → 顯示衝突並要求重新檢視，不靜默覆蓋。

### US-1.6 把資源改掛到既有作品（含修正錯配）
**當**某資源被配錯、或特典需要掛到某作品，**我要**能把它改掛到已存在的作品卡下。

驗收（M）：
1. 待處理資源（如 `WaffleTokuten`）→ 選「掛到現有作品」→ 搜尋 Relirium（v61834）→ 選定 → 確認。
2. 該資源出現在目標作品頁的資源區，不產生新卡；待處理減 1。
3. 已配資源改掛到另一作品 → 原作品不再列出該資源；若原作品因此沒有任何資源，不留下空殼卡（或明確標示無本機檔案）。
4. 之後重新掃描／重新匹配不覆蓋此手動掛載。

### US-1.7 VNDB 連不上或被限速（異常）
**當**匹配途中 VNDB 逾時、斷線或回 429，**我要**匹配暫停並說明原因，進度保留；恢復後能繼續，且不因資料不完整而錯配。

驗收（M，以測試設定把 VNDB 位址指向故障端點）：
1. 故障端點逾時 → 任務進入「暫停/待重試」，Activity 顯示人話原因與「重試」按鈕（G2）。
2. 故障期間：不建立任何新綁定；已完成的綁定保留。
3. 回 429 → 同上，且不狂打重試。
4. 切回正常端點 → 按重試 → 剩餘項目完成，golden 錯配 = 0。
5. 部分回應（不完整結果）→ 該項標「VNDB 結果不完整」而非綁定。
> 🔧 測試前置：目前 VNDB 位址寫死於 `matching.rs`、`metadata.rs`、`exploration.rs`，需要加入僅供測試使用的位址覆寫設定。

### US-1.8 中途關閉／Core 重啟（異常）
**當**掃描或匹配做到一半 Core 被關閉，**我要**重開後看到任務為「已中斷」，按繼續可完成，且不重複建立作品。

驗收（M）：
1. 掃描進行中殺掉 ui_core → 重啟 → Activity 顯示中斷的掃描與「繼續」→ 完成後資源數與一次跑完相同。
2. 匹配進行中殺掉 → 重啟 → 繼續 → 作品數、綁定數與一次跑完相同；無重複卡片。
3. 重啟後不自動無限重試；需求明確的「繼續」動作才恢復。

## 二、瀏覽收藏與作品頁

### US-2.1 用日文原名找到作品
**當**我在 Collection 搜尋框輸入日文原名（或其中一部分），**我要**找到該作品；全形／半形、平假名／片假名差異不影響結果。

驗收（M）：
1. 搜「絡恋インヴィテーション」→ 出現該作品。
2. 搜「やりなおし」（部分字串）→ 出現「やりなおしクランクイン」。
3. 全形／半形變體（如 `ＳＰＩＮ`/`SPIN`、`！`/`!`）→ 結果相同。
4. 搜「だうにゃー」→ 出現「ダウニャーさんと飼い主くん」；平/片假名變體結果相同。
5. 無結果時顯示「找不到」與清除搜尋的方式，而非空白。

### US-2.2 用品牌或人物找作品
**當**我想看某品牌（如 CloverGAME）或某人物（繪師/聲優）的作品，**我要**從作品頁點品牌或人物進入其頁面，看到我收藏中屬於他們的作品。

驗收（M）：
1. 從「やりなおしクランクイン」作品頁點 CloverGAME → 品牌頁列出收藏中 3 部 CloverGAME 作品（やりなおしクランクイン、ダウニャーさんと飼い主くん、こあくまちゃんの誘惑っ！），可直接打開；不在收藏的只連到 VNDB。
2. 從角色/工作人員點進人物頁 → 顯示其參與作品，標明哪些在我的收藏中。
3. 「在不在收藏中」查詢失敗時顯示重試，不顯示成「不在」。

### US-2.3 作品頁必要資訊
**當**我打開任一已配作品頁，**我要**看到：封面、標題、品牌、發售日（與 VNDB 一致）；本機版本/資源與實際路徑（含特典掛在哪）；角色、工作人員、關聯作品且可點擊。

驗收（M）：對 golden 中每部已配作品逐一打開作品頁，檢查：
1. 封面圖載入成功；標題、品牌、發售日非空且與 VNDB 資料一致。
2. 版本區列出資源與其實際路徑，路徑存在於 NAS 測試集。
3. 角色、工作人員、關聯作品區有內容（VNDB 有資料時）且可點入。
4. VNDB 無資料的欄位顯示「未知」，不顯示成錯誤值。

### US-2.4 手動修改與 VNDB 衝突時讓我選
**當**我手動改過標題等欄位，之後重新抓 VNDB 資料而 VNDB 值不同，**我要**系統顯示差異讓我選擇保留哪個。

驗收（M）：
1. Relirium（v61834）手動改標題為「我的Relirium」→ 重新抓 VNDB → 出現差異提示（手動值 vs VNDB 值）。
2. 選「保留我的」→ 標題維持手動值；選「用 VNDB」→ 更新。
3. 未改過的欄位直接更新、不提示。
> ⚠ 需求差異：目前行為是「重抓一律保留手動值、不提示」。需要新增差異選擇功能。

### US-2.5 大量收藏仍可順暢瀏覽（邊界）
**當**收藏有約 3,000 部作品（生成的目錄），**我要**分頁、搜尋、篩選、排序都涵蓋全部收藏且反應迅速。

驗收（M，使用生成的 3,000 作品目錄，不需真實檔案）：
1. 每頁 60 部；翻頁、跳至末頁正確。
2. 搜尋/標籤篩選/排序涵蓋全部而非僅當頁；計數正確。
3. 跨頁選取保留；加入清單時涵蓋所有符合項。
4. 選取超過 10,000 時顯示錯誤（邊界）。
5. 回應時間：搜尋與翻頁 < 1 秒。

## 三、清單與標籤

### US-3.1 從搜尋結果整批建立主題合集
**當**我搜尋或篩選出一組作品（如所有 CloverGAME），**我要**一次全部加入一個新清單，作為主題合集。

驗收（M）：
1. 建立清單「CloverGAME 合集」→ 從品牌篩選結果全選 → 加入 → 預覽顯示 3 部 → 確認。
2. 清單顯示 3 部、封面正確；重開程式後仍在。
3. 重複加入同一作品 → 不產生重複條目，並告知已存在。
4. 大量（US-2.5 目錄）時，「加入篩選結果」涵蓋所有頁而非僅當頁。

### US-3.2 清單條目隨作品變動而跟著走
**當**清單裡的作品被重新綁定、與另一作品合併、或其來源資料夾被移除，**我要**清單條目跟著走、條目筆記不遺失。

驗收（M）：
1. 清單條目寫筆記 → 把該作品合併到另一作品 → 條目指向合併後作品，筆記保留。
2. 移除該作品的來源 → 條目仍在，標示「本機檔案不在」，筆記保留。
3. 重新加入來源並掃描 → 條目恢復正常狀態。

### US-3.3 自訂標籤批次貼上與篩選
**當**我選取多部作品，**我要**一次貼上自訂標籤，並能以此標籤篩選 Collection。

驗收（M）：
1. 建立標籤「年度最愛」→ 選 3 部 → 批次貼上 → 3 部都有此標籤。

## 五、AI 協助配對與多作品資源（2026-10-12 核准）

### US-5.1 AI 建議配對
**當**資源留在待確認，**我要**AI 先幫我找出它是哪部作品，附上建議和理由，由我按確認才生效。

驗收（M）：
1. AI 透過 MCP 為待確認的資源送出建議：VNDB 作品（可以多部）、查到它所用的查詢字、理由。AI 只能建議，不能直接綁定。
2. 待確認列表中，有建議的資源顯示「AI 建議」標記、作品名稱和理由，旁邊有「確認」按鈕。
3. Core 會自動檢查每個建議：能在 VNDB 上對到作品自己的標題或別名，而且品牌或日期也對得上（或資料夾本來就沒寫品牌和日期），就標「已驗證」，其他情況標「未驗證」。只有「已驗證」的建議可以一次批次確認。
4. 確認後立刻出卡或併入已有的卡；之後重新掃描、重新匹配都不會覆蓋，紀錄裡寫明這是人工確認。
5. 資源內容變動後，舊的建議自動失效；沒變動的資源重新掃描，建議會保留。
6. 異常：確認時若資料已被其他操作改動，顯示衝突並要求重新檢視，不靜默覆蓋（同 US-1.5）。

### US-5.2 一個檔案含多部作品
**當**一個資源裝著多部作品（例如 キスイロ、ゆずソフトペンタBOX、ANIM Mother＆Wife），**我要**它同時出現在每一部作品的卡裡。

驗收（M）：
1. VNDB 上連到多部作品、而且不以其中任何一部命名的套裝發行版（純合集），自動把這個資源綁到裡面每一部作品。以某部作品命名的合集仍照 #32 只配到那一部。
2. AI 建議列出多部作品時，確認後綁到每一部。
3. 每張卡的作品頁都列出這個資源並標註「合集」；資源只算一份，檔案不重複計算。
4. 之後若單獨加入其中某部作品的本體，該作品照常配對，不產生重複的卡。
5. 零錯配：只要有任何一部作品無法確定，整個資源留在待確認。
